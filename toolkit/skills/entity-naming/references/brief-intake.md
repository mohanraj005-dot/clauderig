# Brief intake

The single highest-leverage step. In the round that produced Ozarva, the first
wave of thirteen names was rejected wholesale — not because the names were bad,
but because the brief had locked one genre ("Sanskrit-adjacent coined words
ending in -a") and the founder only discovered he wanted something else after
seeing what that genre actually produces. The second wave succeeded because it
deliberately spread across genres instead of committing to one.

So the goal of intake is not to narrow. It is to find out which constraints are
real and which are guesses, and to leave the genre open until there is something
to react to.

## Ask these before generating anything

Batch them into one round. Asking one at a time burns the founder's patience on
the least interesting part of the process.

| # | Question | Why it changes the output |
|---|---|---|
| 1 | What exactly is being named — holding entity, trading brand, or a single outlet? | A holding entity must not sound like any one vertical it owns. An outlet brand should. |
| 2 | Entity suffix — LLP, Pvt Ltd, or none? | Affects rhythm: a name ending in a hard consonant plus "LLP" reads badly aloud. |
| 3 | Which verticals must it stretch across? | A name that works for a café and a gym is a much smaller set than one for a café alone. |
| 4 | Any language or heritage the name should nod to? | Sanskrit-adjacent, Kannada, Anglo, or deliberately abstract — all valid, very different outputs. |
| 5 | Names, words, or prefixes that are off the table? | Cheaper to hear now than after generating forty candidates around a disliked prefix. |
| 6 | Should it encode the founders? | Blended founder names are a real genre but constrain heavily. Ask, do not assume. |
| 7 | Which TLDs must clear? | .com + .in is the usual bar. Dropping .com widens the field enormously — worth naming explicitly as a choice. |
| 8 | Is there a name they already love? | Even if unavailable, it is the best single signal of taste. Ozarva's round started from a rejected favourite. |

## Record it

Write the answers to `naming-brief.md` in the working directory before generating.
It becomes the thing you check candidates against, and the thing you re-read when
the founder rejects a whole wave and you need to work out which assumption broke.

```markdown
# Naming brief — <entity>
| Field | Value |
|---|---|
| Naming | Holding entity / brand / outlet |
| Suffix | LLP |
| Verticals | F&B, gym, co-working, retail |
| Heritage | Sanskrit-adjacent, open to abstract |
| Excluded | "vaj-" prefix, coastal theme |
| Founder link | Optional, mixed |
| TLDs required | .com + .in |
| Loved but gone | Trivista |
```

## Expect to run twice

Treat wave one as a probe, not a delivery. Tell the founder this up front so a
rejected first wave reads as the process working rather than failing. What you
are buying with wave one is a reaction — and reactions to concrete names are far
more informative than anything the intake questions can extract in the abstract.
